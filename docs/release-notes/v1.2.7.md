# SongBrief 1.2.7

## Changes

- Pass the current player's Apple Music catalog ID separately from its local
  persistent ID so registered songs can match despite differing display metadata.
- Validate catalog identifiers consistently across native library mapping,
  playback, history deduplication and library matching. Do not interpret opaque
  MusicKit library IDs as public catalog IDs.
- Prefer the official song URL supplied by MusicKit, including album links with
  a song query parameter, and retain it through cached and persisted history.
- Fall back to Apple Music search when no usable song URL or catalog ID exists.
  Preserve native counters and avoid extra outside-library counts on a match.

## Additional TestFlight Build: Outside-library History Sync

- Keep version `1.2.7`; increment only the build number for this TestFlight update.
- Include confirmed outside-library listening history in private iCloud sync.
  Union exact song/timestamp events, retain a single undated minimum and the
  earliest observation day, and preserve aliases and official song URLs.
- Retry concurrent CloudKit changes by fetching and merging again. Retain local
  evidence on network errors and include records added during an in-flight save.
- Sync on foreground/refresh and debounce new local evidence. The iCloud toggle
  controls this sync independently of daily snapshot recording or history display.
- Show a partial sync state when only one history source succeeds. Compress
  larger ledger payloads without discarding records; oversized compressed records
  remain local and report a sync error.
- Local validation: 388 Flutter tests and static analysis passed, including
  two-device convergence, offline/conflict handling, in-flight changes, preference
  restoration and settings behavior. Native CloudKit tests run in release CI.
