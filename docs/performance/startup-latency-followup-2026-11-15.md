# 起動時間と残る短い停止の追加調査

## 採用した変更

- 下部ナビゲーションを const の独立した ConsumerWidget とし、選択状態だけを内部で購読する。読み込み完了時に、準備済みの NavigationBar の Widget 自体も再利用する。読み込み完了時に TickerMode の継承値を変更する処理も除いた。読み込み中の非表示・フォーカス除外は維持。
- 再生中パネルの画面外の履歴は、そのパネルの構築時に初めて購読する。ネイティブの大きいライブラリの履歴統合を、ヒーローの初回構築時に実行しない。
- デモの90日分の履歴を、日別カウンターから直接生成する。各日について LibraryOverview（ランキング・検索索引・プレイリスト等）を作り直す処理を除いた。曲ごとの日別増分も一度だけ計算し、後ろから累積する。日付、曲情報、各日のカウンター、最終合計は維持する。

表示を固定時間待たせる処理は追加していない。画像の縮小、再生ボタンの実装簡素化、Webの主フォント変更も試したが、明確な性能改善を確認できず、すべて元に戻した。

## 計測方法

Windows の実ブラウザ（Chromium IAB）、CanvasKit、390×844、デモ1,000曲。キャッシュを温めた localhost の通常起動を変更前（8821）・修正後（8825）交互に各3回測定。CPU Profiler、ビルド、テストを計測中には実行していない。通常起動は `loading_preview` なし。比較用の preview は従来どおり4秒の意図的待機あり。

`songbrief-content-frame` は Flutter の post-frame callback。レイアウト・ペイント処理の完了の目安であり、GPUの表示完了時刻ではない。`flutter-first-frame` も併記し、ページ読み込みから最初のFlutter画面までの時間と、データ到着後の切り替え区間を分けて評価した。

## 結果

| 通常起動・profile（ms） | 変更前 各3回 | 修正後 各3回 | 中央値 前→後 |
| --- | --- | --- | --- |
| ページ読み込みから最初のFlutter画面 | 1379.8 / 1328.2 / 1569.6 | 422.8 / 489.0 / 332.7 | 1379.8 → 422.8 |
| loading から data-ready | 1051.5 / 1004.5 / 1203.8 | 44.9 / 57.4 / 37.6 | 1051.5 → 44.9 |
| data-ready から content-frame | 106.7 / 117.0 / 112.4 | 94.6 / 135.3 / 92.0 | 112.4 → 94.6 |

初回表示は約69%短縮。大きいデモ履歴の生成が初回フレームをブロックしていた影響が大きい。一方、データ到着後の処理は中央値で約16%減ったものの、135.3msの回もあり、約100ms級の停止は残る。

公開用と同じ release 設定でも修正後を3回測定した（8826）。最初のFlutter画面は401.9 / 356.5 / 292.9ms、中央値356.5ms。data-ready→content-frame は104.0 / 96.5 / 88.7ms。profileとの値を混ぜて改善率は算出しない。

従来と同じ4秒待機を入れた切り替え単独の比較では、最大rAF間隔の中央値は今回の変更前66.7ms、修正後80.0ms。少数回でばらつきがあり、この指標の改善は確認できなかった。前回の約107msが今回の変更前では約67msとなったため、前回値との単純な差分を今回の修正効果として扱わない。

前回の62.8→101.6msは data-ready→content-frame の区間で、ページ読み込みからの初回表示時間ではない。今回、通常起動のページ読み込み起点も測り直し、初回表示全体の悪化が続いている状況ではないことを確認した。切り替えだけの時間は今回も悪い回が残る。

## 原因の切り分け・限界

V8 CPUサンプリングを NavigationStart の単調時刻と照合すると、切り替え時にテキストの初回レイアウト、WebGLのシェーダー・プログラム準備、画像転送が集中していた。ウィジェット別計測でも新規のナビゲーション構築・ヒーロー・テキストの初回レイアウトを確認。CPU計測用の負荷は通常比較には含めていない。

デモ生成の改善はWebデモとネイティブのデモ表示に適用される。ネイティブの実ライブラリは履歴パネル購読の遅延が対象。iPhone/iPadのネイティブ実機計測は今回実施していない。冷たいネットワークキャッシュでの初回ダウンロード時間も、この比較の対象外。

## 検証

- 起動・通常ウィジェット・デモ履歴の37件成功。
- 変更前の生成器から保存した90日分すべてのカウンターに一致する回帰テストを追加。曲メタデータ、日付順、朝6時の記録、最終合計も検証。
- 起動時の NavigationBar の Element と Widget の両方の同一性を検証。
- 画面外の履歴プロバイダーが未計算で、スクロールで初めて計算されることを検証。
- 関連ファイルの dart analyze：問題なし。git diff --check：エラーなし（既存の改行コード警告のみ）。
- Web profile / release ビルド成功。既存の CupertinoIcons フォント参照警告は継続。
